## 2. P0 总清单（大版本动工前必须先修）

### 2.1 数据安全类（可造成用户文件永久丢失）

**S1 · 台账吞错 → 孤儿 GC 可清空整个 vault**
`ledger.rs:292-299` `live_manifest_ids()` 在 prepare 失败或行级解码错误时**静默返回空表**（`filter_map(r.ok())` + `unwrap_or_default`）；`vault.rs:216-228` 的孤儿 GC 把"不在名单内"的会话目录一律 `remove_dir_all`。台账 DB 损坏、被安全软件锁文件（本机 E1 背景真实存在）、某行含非法 UTF-8 → 名单变空 → **全部 7 天内的暂存副本被物理删除且台账同步失真**。GC 无"取名单失败就不做 GC"熔断。
→ 修：`live_manifest_ids` 返回 `Result`；Err 时跳过 GC；待删目录加 mtime > 24h 宽限双条件；`vault_copies`/`undo_entries`（ledger.rs:304-335）同款吞错一并改错误传播。

**S2 · stash→save 无 journal，崩溃即孤儿，孤儿即被 GC 删除**
时序是"逐条 rename/copy 完成（`executor/mod.rs:88`）→ 最后才写台账（mod.rs:123-129）"。rename 成功瞬间掉电、或写盘前报错（磁盘满/DB 锁/busy 超时——SQLite 未开 WAL），源文件已离开原位、vault 有实体、台账零记录；应用启动即跑 sweep+GC（`src-tauri/src/lib.rs:94`），下次启动这批数据**直接被当孤儿删掉**。这违反 HANDOVER §3.1 自己钉的"禁止台账外无主副本"不变量。`vault_delete`（src-tauri/src/lib.rs:416-442）与 CLI `zclean vault`（zc-cli/src/main.rs:383 后）同病。
→ 修：stash 前先落 `status='pending'` 台账行，逐条成功 UPDATE 为 committed；pending 行 GC 永不触碰。

**S3 · `manual-<unix秒>` 批次 id 碰撞 → 整批台账被覆盖抹除**
GUI（src-tauri/src/lib.rs:414）与 CLI（zc-cli/src/main.rs:381）的手工暂存 id 都是秒级时间戳；同秒两次操作共用 session 目录与主键，`upsert_manifest` 是 `INSERT OR REPLACE` + `DELETE FROM entries`（ledger.rs:72-87）→ 第一批台账瞬间清空 → 其 vault 副本变孤儿 → 接 S1 被删。
→ 修：id 换 `new_session_id()` 级熵（scanner.rs:85-91）；id 已存在且 entries 非空时显式报错而非覆盖。

**S4 · Guard 禁删区硬编码 C 盘 + USERPROFILE 缺失 fail-open**
`guard.rs:11-16` 写死 `C:\Windows`/`C:\ProgramData` 等；系统装在 D:/其他盘符的机器上，真实 Windows 树**零保护**。`guard.rs:20-23` USERPROFILE 未定义时返回空表——文档/桌面/下载保护**静默消失**，这是守卫里唯一的 fail-open 分支。`guard.rs:39-41` 自保护依赖 LOCALAPPDATA 字面量，`ZC_DATA_DIR` 重定向的便携模式下 vault 本体不在保护名单，规则可以把自己的暂存区扫进来。
→ 修：禁删根由 `%SystemRoot%`/`%ProgramFiles%`/`%ProgramData%` 派生；USERPROFILE 缺失时 vet 返回 Err；self_protected 用 `manifest::data_dir()`。

**S5 · 启动项禁用顺序反了 + 失败仍清账**
`startup.rs:145` 先 `RegDeleteValueW` 后 `save_backup`（:151-158）——两步之间进程被杀/写盘失败，该项既出注册表又无备份，**还原凭据永久丢失**（本机 E1 软件 3 秒抹值，此窗口不学术）。`enable_all` 无论逐项成败结尾无条件清空备份文件（:185），回写失败项从此不可恢复。备份 JSON 损坏静默当空（:121-125），禁用项无对账、恢复无延时校验。
→ 修：先落备份再删值；enable_all 只清除成功回写项并返回明细；写后校验。

### 2.2 架构矛盾类（宣称能力 ≠ 实际能力）

**A1 · Guard ↔ admin 规则死锁：9 条规则扫得出、永远清不掉，还会毒死整批**
`zc-rules/src/lib.rs:49-78、219-221` 的 9 条 `admin_required` 规则（系统 Temp、SoftwareDistribution/Download、DeliveryOptimization、FontCache、Prefetch、kernel dumps、WU logs、PerfLogs、CBS）目标全在 `C:\Windows`/`C:\ProgramData` 禁删前缀下；`executor/mod.rs:61` 对**全部命中**无差别 `vet()` 且任一违规 `?` 上抛整批失败；提权 worker 也走同一 apply（`elevate.rs:127`）。`guard.rs:15` 注释自述"清理走 admin worker 白名单"——**该白名单在全仓不存在**（vet 四个调用点均无豁免）。后果链：勾选含任一 admin 规则 → 整批 Err（连坐正常规则）；用户"特意管理员运行 + `--admin`"→ CLI 此时不再剔除 admin 规则（main.rs:234 条件短路）→ **提权反而保证失败**。README"60 条规则"与 docs/rules.md 的 ⚙ 标记共同构成"功能存在"的假象。
→ 修：`Guard::vet` 增 elevated_allowlist（仅提权 worker 注入），逐条**目录级**豁免这 9 个已知安全目录，Windows 树其余部分仍 fail-closed；补一条端到端集成测试。

**A2 · 回收站清空能力为零**
全仓（规则层+执行层+UI+CLI）无 `SHEmptyRecycleBin`/清空 `$Recycle.Bin` 的任何形态（grep 零命中）——`CleanMode::RecycleBin` 只是"送进"回收站。回收站常年 5–30 GB，是**单条最高收益缺失项**；History 页 recycle_bin 批次也只有一行灰字（History.tsx:97-99），无"打开回收站"入口。

**A3 · reboot.rs 死代码**
`executor/reboot.rs` MoveFileExW 重启删除队列实现正确但**全仓零调用者**——文档暗示的"锁定文件重启兜底"未落地。要么接入 trash 逐项失败分支，要么删除并更正 HANDOVER。

### 2.3 UI 闭环类（用户可感知的言行不一）

**U1 · Results 页：一次性死胡同 + 危险操作零确认（与设置页承诺直接矛盾）**
`Settings.tsx:39` 宣称"注意及以上档位需逐条展开二次确认（UI 强制）"；实际 `Results.tsx:66、158-159` 对 safe/caution/risky/expert 任何档位都是一键勾选+底部一键执行。且 Results 不在侧栏 NAV（App.tsx:22-33），唯一入口是扫描完成的一次性 phase 跃迁（App.tsx:48）——切页后 report 仍在 store 但**全 UI 无任何再入路径**，selection"跨页保留"实为伪保留。命令面板在 results 页再触发扫描会让页面停留并渲染"共 0 B"空壳（无加载态）。

**U2 · undo/purge 成功后 History 行不刷新**
`store.ts:210-238` 只清战报弹 toast，history 数组原封不动 → 已还原批次仍挂列表，再点必报"台账不存在"（对比 `manualDelete` store.ts:248-251 是正确的）。必现级。

**U3 · init 失败静默半残**
`store.ts:99-110` 五路并发 fetch 任一 reject 被 `void init()`（App.tsx:45）吞掉 → 无 drives/rules 的半残 UI 永久空白；rules 缺失还会导致下次扫描"0 条规则可勾"（store.ts:130）。

**U4 · 清理遮罩：每 1.4 秒自我重挂载 + 文案撒谎**
`CleaningOverlay.tsx:34` `key={String(idx)}` 挂在整张 fixed 遮罩上，规则名每 1.4s 轮换 → 遮罩整体 remount：0.25s 淡出+0.18s 淡入+卡片弹簧重放+spinner 从 0° 重转，玻璃化精装每 1.4s 抖一次。`:57` 写"后台执行，可切走"，但 `fixed inset-0 z-[55]` 无关闭按钮——**根本切不走**，清理期间整个应用锁死且无进度百分比、无取消。

**U5 · ErrorBoundary 崩一次全站崩**
边界包在 AnimatePresence 外层（App.tsx:153-167），`error` state 不随切页复位——任一页崩一次，切到任何页都仍是崩溃卡；卡上文案"其余页面不受影响；回到体检台可继续"（ErrorBoundary.tsx:41-43）与实现相反（没有回体检台按钮），稳定崩因下"重试本页"是死循环。修法一行：`<ErrorBoundary key={page}>`。

### 2.4 壳层/系统类

**T1 · migrate_undo 是同步主线程重 IO**（src-tauri/src/lib.rs:594-601）：全壳唯一正面违反"重任务不下主线程"纪律的命令，跨盘/被占用回退复制时冻结事件循环。
**T2 · migrate_apply 失败路径不失效雷达缓存**（lib.rs:588）：Link 阶段后失败（junction 已建成）早退，`analyze_cache_invalidate()` 不执行——违反 §3.3 契约的实质违例点。
**T3 · 无单实例插件**：双进程 → 两个启动 sweep 并发、SQLite 同库竞争、双扫描抢 CPU；QA 脚本也假定单实例。
**T4 · 提权通道安全与健壮性**（elevate.rs）：①PowerShell 命令**单引号裸插值**（:74-77），路径含 `'` 即断（用户名带撇号就触发）兼注入面；②提权 worker **盲读任意 report_path 的 JSON 决定删哪些路径**（:117-127），无签名/nonce/来源锚定——同用户恶意进程可预写报告借管理员权限删除禁删名单外路径（LPE 面）；③worker panic 则 launcher 干等 15 分钟（main.rs:256）；④结果文件非原子写（main.rs:341），200ms 轮询可读到半截 JSON。

## 3. 分域详评与优化方向

### A. 内核（crates/zc-core）

除 §2 的 S1-S5 外，P1 级问题：

- **scanner 是"宣传并行、实际串行"+ O(文件数×深度) 锁热点**：jwalk 0.8 `into_iter()` 为串行栈式（无爆栈风险，但 `lib.rs:5` "并行 Walk 引擎"名不副实）；`scanner.rs:144-150` 对每个文件沿祖先链逐级 `entry()` + PathBuf 克隆 + 全局 Mutex——恰是 analyze.rs:3-6 注释声讨并已重构掉的反模式，在扫描器里原地复活。百万文件级目录非线性膨胀。→ 改"只记直接父 + 自底向上聚合"，开 rayon 并行 + per-thread map 合并。
- **dedup_nested 大小写双计数 bug**（scanner.rs:223 vs 227-231）：排序用原始字节序、吞并用小写 norm，NTFS 同父混大小写名时子可排在父之前不被吞并 → 父+子双提交；vault 场景用户看到假 failed（实际已随父进暂存区）。
- **取消契约靠自觉**：半途取消的报告照常带 hits 返回（scanner.rs:200 只挂 cancelled 标志），调用方不查标志就能 apply 半截结果；`cancel_scan` 与 `scan()` 入口 `reset()` 有竞态窗口（取消被抹掉）。→ 世代号或运行中才接受取消。
- **cancel 后 AccessDenied 子树静默少报**（scanner.rs:129）：skip 不计数，"诚实口径"在最需要诚实的地方失声。→ ScanReport 加 `skipped_dirs` 字段并在 UI 显示"N 处无法读取"。
- **overflow 虚高**：>5 万条后 overflow_bytes 计入 cleanable_bytes（models.rs:56-62）但 executor 只搬明细 hits → 大缓存下报告虚高"清不掉的部分"。
- **SQLite 未开 WAL**（ledger.rs:184-186）：读历史长查询与写台账互斥，busy 5s 超时后"清理成功但台账写失败"——又落 S2 窗口。
- **actual_size/copy_all 递归实现**（vault.rs:39-59、102-113）：深目录爆栈概率低但可归零；跨盘 copy 回退对 OneDrive 占位文件（全仓无 `RECALL_ON_DATA_ACCESS` 处理）会触发云端水合拉流。
- **trash 批量失败降级说谎**（executor/mod.rs:66-84）：逐项重试对"其实已被批量搬走"的文件也报 failed，"已原样保留"文案对回收站里的文件说谎；先 `p.exists()` 甄别。O(n²) 的 `hits.iter().find` 回查（mod.rs:104,118）改 HashMap 预索引。
- **测试卫生**：`tests/e2e_fixture.rs:23,67` 三测试并行 `env::set_var("ZC_DATA_DIR")` 无 DATA_LOCK（edition 升 2024 直接编译不过）；guard fuzz 未覆盖 junction、8.3 短名、非 UTF-8、`SystemDrive≠C:`——恰好测不出 S4。
- **unwrap/expect 清单**（生产码）：vault.rs:67,78（数据目录不可写 → spawn_blocking 线程 panic、命令悬空）、scanner.rs:147,175,210（锁中毒连锁 panic）。库层不该 panic。

### B. 规则与扫描路径（crates/zc-rules + analyze/dedup）

**60 条规则构成**：System 13（9 条被 A1 卡死）、Browser 11、Dev 24、Apps 10、Logs 2。书写纪律好（宏生成+id 唯一/风险默认/admin 一致性自动单测），加新规则成本低，但 **`pub const RULES` 编译期数组 = 用户不可自定义/不可禁用，必须重编译发版**（lib.rs:44）。

**高收益缺失 TOP5**（这是"内容的完整度、扫描路径落地性"的核心答案）：
1. **清空回收站**（A2，5–30 GB）；
2. **国产 IM/办公缓存**——微信 4.x（xwechat_files）、QQNT 图片视频缓存（现仅 QQ 崩溃报告，lib.rs:202）、钉钉、飞书、企微，对中文用户是第二大缺口；
3. **pnpm store**（常 5–30 GB；现规则只清 pnpm-state 数 MB，名不副实，lib.rs:124-125）；同类：`.m2/repository` 本体、npm 旧版 `%APPDATA%\npm-cache`；
4. **9 条 admin 规则打通**（A1；合计常 2–20 GB——SoftwareDistribution 单条就 1–10 GB）；
5. **Windows.old 清理**（现在只有只读盘点 `system_occupancy`；需所有权/ACL 处理，至少做"引导+一键跳 Disk Cleanup"闭环）。

其他覆盖空白：Chromium/Electron 套壳（Teams/网易云等）、Chrome Beta/Dev、Brave/Opera/Vivaldi 缺 Code Cache/GPUCache 与多 profile（lib.rs:99-113）、Firefox 崩溃报告、INetCache、WER 系统级、`C:\Windows\Logs` 其余子目录、Java/Flash 遗留、剪贴板历史、VS Code 本体 Cache/logs、Bazel out 树、WebView2 宿主缓存。
**路径写法**：全库硬编码 `C:/Windows/...` 而非 `%WINDIR%`（patterns.rs:11 明明支持）、用户 Temp 用 `%LOCALAPPDATA%/Temp` 而非 `%TEMP%`——TEMP 改址/非 C 系统盘用户整库失灵。

**风险档校正**：dev-playwright Safe→Caution（lib.rs:149，删后离线环境不可恢复）、sys-kernel-dumps Caution→Risky（:71）、sys-prefetch 性价比存疑（收益小、首启变慢负作用）。规则缺 `min_age`（"只删 7 天前的"）、缺 service-stop 声明（wuauserv/DoSvc/FontCache 持锁即使打通 A1 也清不动）、缺收益估算字段。

**analyze.rs（雷达体积树）**：三段式聚合架构正确 O(files+dirs)，但①每文件抢一把全局 Mutex（analyze.rs:53-78）并行度被锁吃光；②`build_tree` 无取消令牌——关雷达页遍历也停不下来；③逻辑字节口径——稀疏文件（WSL/VHDX）严重虚高、压缩/EFS 按展开计、硬链接重复计数，与"诚实口径"卖点冲突 → 换 `GetCompressedFileSizeW`；④折叠节点 `files=0` 语义与字段名不符。

**dedup.rs**：size→64KB 头预哈希→XXH3-128 全量三级管道是业界正确姿势，但：无硬链接防护（同文件多路径互为"重复"，purge 后收益全假——需 (volume,file_id) 归并）、**云占位文件打开即触发海量下载**（jwalk 不拦 reparse 文件点）、无内存上界（全盘去重 PathBuf 可堆积 GB 级）、组无 volume 字段 UI 无法区分同盘/跨盘、纯 hash 定组无末级字节比对（128-bit 可接受，写明即可）。

### C. Tauri 壳 / IPC / 系统集成

**真实完成度**：v4.1.0 提交宣称 13 项精装，11 项真实现（Toast 三件套最扎实：4.2s 与 store 严格同参；Ring 渐变+辉光、shimmer、页面转场 100% 接入、氛围光背景均属实）。虚的：**`.zc-lift` 全工程 0 使用**（CSS 死码）；三档海拔实际"名义三档、实用两轨别名、多数卡片零海拔"。

## 4. 大版本（暂称 v5.0）主题建议

按"用户可感知的价值"组织的六条主线，每条都是自包含批次，可独立发版：

**主线一：安全底座补课（信任叙事，v5.0 的技术前提）**
S1-S5 + A1 + T4 全量修复；journal 化 stash 事务 + WAL；guard 环境变量化 + 提权白名单 + 端到端集成测试；elevated worker nonce 锚定；单实例插件。→ 叙事："暂存区从设计上不可能丢数据"。

**主线二：可清理面翻倍数（产品最大短板）**
清空回收站（SHEmptyRecycleBin，首页一键+History 入口）、9 条 admin 规则经白名单真实打通（Windows Update/系统 Temp/传递优化——宣传主力收益项从 0 到可用）、微信/QQNT/钉钉/飞书缓存规则、pnpm store/.m2 补全、Windows.old 引导闭环、浏览器规则补全（Brave/Opera/Vivaldi/Chrome Beta/Firefox 崩溃报告）。规则表加 `min_age_days` 与 service-stop 声明，Temp/WER 类默认"仅 7 天前"。→ 叙事："一次体检真正能释放的空间翻倍"。

**主线三：从一次性操作到持续管理（功能完整度升维）**
规则管理页（清单/启停/收益预估/自定义规则文件 rules.d/*.json——当前完全不可自定义是最大产品缺口）、排除目录、多分区与任意根分析（打通雷达 path 参数与磁盘环点击）、定时/自动清理计划、系统通知+托盘+启动后台静默、导出报告。迁移后台化做全（阶段事件入 store、切页重连、迁移历史+事后撤销，兑现现有假承诺）。

**主线四：闭环与文案诚信（修掉所有"言行不一"）**
U1-U5 + Results 可再入 + 危险确认全站统一 armed + History 刷新/批次明细下钻 + init 错误条 + CleaningOverlay 去 remount/真可切走/加进度与取消 + 各页失败不再伪装空态 + 1.2s 垫时删除 + 所有"承诺文案"与实现对齐审计。

**主线五：设计系统 v4（感知质量）**
浅色主题整体补课（色板/海拔/hover 令牌化，或先撤出选项止损）；Treemap FLIP/transform 化 + hover 事件委托；RollNumber 修中断+并入 motion value；列表 exit+key 去 index；22 处私定缓动收编进词汇表（补 pulseDot/overlayIn 词）；转场 wait→crossfade（0.55s→0.3s）；按钮按压态普查；键盘（Treemap/Tools 卡 Enter 提交/focus trap/Esc 解除 arm）；overscroll/focus-visible/主题 bootstrap。

**主线六：质量与发布工程（支撑以上五条不回归）**
vault/migrate/sweep/startup 硬约束回归测试（Rust 层）；契约静态检查（写命令必须含 cache_invalidate 的 lint）；qa_cli.py（ZC_DATA_DIR 隔离跑全 CLI 链路，顺带治 T3 陈旧二进制）；QA 三态计数+失败截图+git SHA 入报告+用例锁定夹具行；CDP 客户端补分帧；CHANGELOG/README/portable 同步脚本化进 CI（tag 有 CHANGELOG 无 → 红）；发布校验脚本（latest.json.version==tag、四资产、sig 验证）替代人工 curl；winget 事实澄清+回填；遗留物清理；文档全面纠偏。

**建议施工顺序**：一 → 二 → 四 → 三 → 五 → 六穿插。主线一二是"必须"（数据安全+产品价值），主线四是 v5 的口碑底线（所有 bug 都长在用户信任路径上），三五可以并行分人。若大版本周期紧，主线一、二、四合起来构成最小可信 v5.0。
