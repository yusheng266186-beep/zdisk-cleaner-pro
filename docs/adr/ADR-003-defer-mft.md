# ADR-003 · MFT 直读引擎推迟；Walk 引擎已满足性能验收线

状态：已接受 · 2026-08-27

## 背景

REBUILD_V3_PLAN 的 Phase 4b 计划引入 NTFS $MFT 直读（`ntfs-reader`/`mft` crate）把全盘扫描降到秒级。实施前评估发现三个硬事实：

1. 读 `$MFT` 需要**管理员令牌**（backup semantics 打开卷句柄），而当前开发/CI 环境均为非提权——写出来的代码无法在本轮闭环验证；
2. 实测 Walk 引擎在目标硬件上已达标：60 条规则全量扫描 28,236 文件仅 **3.9s、峰值内存 ≈17MB**（`docs/benchmarks.md`），远优于 ≤20s 验收线；
3. 直读绕过文件系统过滤器驱动，需要处理稀疏属性、USN 回放一致性、安全软件兼容降级——没有真机提权验证就是闭眼上架。

## 决策

- **推迟** MFT 引擎与 USN 增量缓存至 beta 后评估；
- 性能预算改由三件事承担：Walk 引擎并行调优、扫描索引 SQLite 缓存（ADR-002 迁移计划内）、规则根目录裁剪；
- 重启条件：拿到管理员可用环境做 weekly spike，或真实大盘（>500k 文件）实测超线。

## 后果

- 正面：内核依赖树里少一个高风险特性开关；本轮交付时间确定。
- 风险：超大 NTFS 卷（系统盘 100 万+ 文件）首扫可能突破 20s 预算——届时优先启用索引缓存而非提前上 MFT。
